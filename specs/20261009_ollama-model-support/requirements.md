# 需求规格：ollama-model-support（模型接入支持 Ollama 本地/内网）

> 挂载: **v2.0.0**（在途；2026-10-09 启动版本问句确认）｜来源: **BL-29**（用户 2026-10-05 列入待办；2026-10-09 口令「进入建设」）
> 影响面: admin-ui 模型配置 + 运行时模型装配（phoenix-agent harness）+ 向量维度（数据面）

## 背景与目标

**为什么做**：平台现有模型接入只面向公有云 OpenAI 兼容服务（deepseek / qwen / openai / siliconflow / custom），
私有化、内网、离线场景无法接入本地模型。Ollama 是内网/离线部署最常见的本地模型运行方式（用户本机已装，0.40.2）。

**成功长什么样（可度量）**：
1. 用户在 admin-ui 模型配置中选 provider=`ollama` → 连通并**从本机拉取模型列表** → 保存并启用/设默认；
2. 三类模型类型（CHAT / MULTIMODAL / EMBEDDING）各至少一条 Ollama 配置行完成「连接测试通过」；
3. 一个 harness 智能体绑定 Ollama CHAT 模型后，完成**含工具调用**的一轮对话（工具被真实执行、结果回填、流式输出正常）；
4. 多模态场景用本地视觉模型完成一次图片理解（与现有附件链路一致）；
5. Embedding 场景：Ollama embedding 模型完成知识入库并检索成功（非 512 维亦可用，见 R-08/R-09）；
6. 全程**不依赖外网**（离线交付环境可用）。

## 需求条款

### R-01 Ollama 作为一等提供商

WHERE 用户在模型配置中选择「提供商」，
系统 SHALL 提供 `ollama` 选项，并在选中后预填默认 API 地址模板（容器访问宿主：`http://host.docker.internal:11434`），
同时允许用户改写为内网 IP 或其它端口。

#### 验收场景
- **GIVEN** 打开模型配置新增表单
  **WHEN** 展开「提供商」下拉
  **THEN** 列表中出现 `ollama`；选择后 API 地址被自动填入默认模板且可编辑
- **GIVEN** 选择 `ollama` 后将地址改为内网地址
  **WHEN** 保存
  **THEN** 保存成功，地址以用户填写值为准（不被模板覆盖）

### R-02 Ollama 的 API Key 可留空

IF 提供商为 `ollama`，
系统 SHALL 允许「API 密钥」留空完成保存、启用、设默认与调用，且不以"密钥为空"为由拒绝。

#### 验收场景
- **GIVEN** 新增 `ollama` 配置且密钥留空
  **WHEN** 提交表单
  **THEN** 校验通过、保存成功
- **GIVEN** 上述配置已保存
  **WHEN** 点击「连接测试」
  **THEN** 不因密钥为空报错（连通性结论只取决于服务可达与模型存在）

### R-03 三类模型类型全覆盖

系统 SHALL 支持 Ollama 承载 `CHAT`、`MULTIMODAL`、`EMBEDDING` 三类模型类型，
且复用现有类型语义（同类型默认行唯一、启用/停用/设默认规则不变）。

#### 验收场景
- **GIVEN** 本机已装对话模型、视觉模型、embedding 模型各一
  **WHEN** 分别建三条 Ollama 配置（类型分别为 CHAT / MULTIMODAL / EMBEDDING）
  **THEN** 三条均可保存、启用，且可各自设为对应类型的默认行
- **GIVEN** 某类型已有一条 Ollama 默认行
  **WHEN** 直接停用该行
  **THEN** 按既有守卫拒绝并给出「先启用另一条同类型模型并设为默认」的可操作提示

### R-04 连通性测试覆盖 Ollama 全类型

WHEN 用户对 provider=`ollama` 的配置行点击「连接测试」，
系统 SHALL 在 60 秒内返回"可用/不可用"结论，且三类模型类型均有测试通路；
失败时 SHALL 呈现 provider/Ollama 的原始错误要点（不吞成泛化提示）。

#### 验收场景
- **GIVEN** 本机 Ollama 正常运行且模型已存在
  **WHEN** 对 CHAT / MULTIMODAL / EMBEDDING 三条 Ollama 行分别测试
  **THEN** 三条均返回可用
- **GIVEN** 地址指向一个不可达端口
  **WHEN** 测试
  **THEN** 返回不可用并给出连接类错误要点（可据此定位是地址、端口还是模型名问题）

### R-05 拉取本机模型列表供选择

WHEN 用户在 provider=`ollama` 的表单中触发「获取模型列表」，
系统 SHALL 通过 Ollama 的模型列表接口读取本机已安装模型，并在「模型名称」处提供可选择（可搜索）的下拉；
当服务不可达或无模型时，系统 SHALL 退化为手工输入并给出明确提示。

#### 验收场景
- **GIVEN** 本机 Ollama 有已安装模型
  **WHEN** 触发获取模型列表
  **THEN** 下拉中出现全部本机模型名（含 tag），可选中并带入模型名称
- **GIVEN** Ollama 未启动
  **WHEN** 触发获取模型列表
  **THEN** 提示失败原因，且「模型名称」仍可手工输入、保存不受阻

### R-06 对话链路可用（含流式）

WHEN 智能体绑定（或默认回退到）Ollama CHAT 模型并接收一轮用户消息，
系统 SHALL 正常流式输出回答，行为与既有公有云模型一致（帧格式、结束语义、错误提示一致）。

#### 验收场景
- **GIVEN** 一个 harness 智能体绑定 Ollama CHAT 模型
  **WHEN** 发送一条普通问答
  **THEN** 前端可见逐字流式输出并正常结束（无长时间"正在执行"残留）
- **GIVEN** 同上
  **WHEN** 提问过程中 Ollama 服务被中断
  **THEN** 前端收到明确失败提示（含提供方原文要点），会话可继续下一轮

### R-07 工具调用可用，且能力差异有降级提示

WHEN 智能体绑定 Ollama CHAT 模型且该模型支持工具调用，
系统 SHALL 正常执行平台工具（如知识库检索）并回填结果；
IF 所用模型不支持工具调用或返回格式无法解析，
系统 SHALL 给出可诊断的提示或降级行为，**不得静默失败或空答**。

#### 验收场景
- **GIVEN** Ollama 已装支持工具调用的模型（如 qwen2.5/qwen3 系）并绑定给智能体
  **WHEN** 用户提出需要知识库检索的问题
  **THEN** 工具被真实调用、结果回填并产出回答
- **GIVEN** 绑定的是不支持工具调用的模型（本机 `gemma3:latest`）
  **WHEN** 用户提出同类问题
  **THEN** 系统给出"该模型不支持工具调用"类可诊断提示（而非空答或长时间挂起）

### R-08 Embedding 维度不再固定为 512

WHERE 使用 Ollama（或其它 provider）的 embedding 模型，
系统 SHALL 以其**实际输出维度**为准完成向量入库与检索（覆盖 768 / 1024 等常见维度），
不得因维度非 512 而失败。

#### 验收场景
- **GIVEN** 配置一个 768 维或 1024 维的 Ollama embedding 模型
  **WHEN** 上传知识文档并触发入库
  **THEN** 向量成功写入且状态为完成（维度与模型一致）
- **GIVEN** 上述数据已入库
  **WHEN** 发起检索
  **THEN** 命中结果与语义相符

### R-09 维度不一致必须显式拒绝（防脏数据）

IF 当前配置的 embedding 维度与目标向量表既有维度不一致，
系统 SHALL 在入库/检索前拒绝并明确告知（写明两个维度与处置建议），**不得静默写入**。

#### 验收场景
- **GIVEN** 库内已有 512 维向量，当前默认 embedding 被换成 1024 维模型
  **WHEN** 触发新知识入库
  **THEN** 拒绝写入并提示维度不一致及所需动作（重建/切换）

### R-10 离线与内网可用

WHERE 部署在无外网的内网环境，
系统 SHALL 在与 Ollama 交互的全过程不依赖任何外部网络（模型列表、连接测试、对话、向量化均只访问配置的本地地址）。

#### 验收场景
- **GIVEN** 容器仅能访问内网 Ollama
  **WHEN** 依次执行 连接测试 / 获取模型列表 / 一轮对话 / 一次知识入库
  **THEN** 全部成功，且过程不产生对外部域名的访问

### R-11 可诊断性

WHEN 发生 Ollama 相关调用，
系统 SHALL 记录足以定位问题的关键信息（模型名、端点、耗时、错误要点，密钥不落日志），
且与既有 provider 的日志口径一致。

#### 验收场景
- **GIVEN** 一次失败的 Ollama 连接测试
  **WHEN** 查看后端日志
  **THEN** 可看到模型名/端点/失败原因（无密钥明文）

## Non-goals（范围外）

- **不做** Ollama 的模型生命周期管理（下载 `pull`、删除 `rm`、导入模型）——平台只列出与使用已装模型
- **不做** Ollama 原生 `/api/generate` 协议的独立适配（走框架既有的 Ollama 适配层，见 plan）
- **不做** GPU/显存调度、多 Ollama 实例负载均衡与故障转移
- **不做** Ollama 侧的用户鉴权/多租户隔离（本地服务默认无鉴权）
- **不做** 模型能力的自动探测与自动选型（是否支持工具调用由用户选型负责，系统只做提示）
- **不做** 存量 512 维向量的**自动**重建（仅提供拒绝提示与迁移指引；如需自动重建见待确认问题 Q2）

## 我正在做的假设

1. 框架侧已具备 Ollama 适配能力（`agentscope-extensions-model-ollama:2.0.0`，jar 已在本机 maven 仓）——若需新增外网依赖，本需求需回到 plan 重议（如不成立请现在指出）。
2. 用户本机 Ollama 版本 0.40.2，已装 `gemma3:latest`（视觉可用、**不支持工具调用**）；工具调用与 embedding 验收所需模型需另行安装。
3. 容器访问宿主的写法 `host.docker.internal:11434` 可用（本次已实测容器内返回 `{"version":"0.40.2"}`）。
4. 向量维度可变意味着**既有 512 维向量数据不可与新维度混用**（接受"显式拒绝 + 重建"的处置方式）。
5. `tbl_data_model_config` 现有列（provider/base_url/api_key/model_name/model_type）足够承载 Ollama，无 DDL 必改项（api_key 若为 NOT NULL 则存空串）。
