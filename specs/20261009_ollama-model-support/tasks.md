## 1. 基础（依赖与类型）

- [x] T-01 引入 Ollama 扩展依赖并把 harness 模型类型从具体类上移到框架抽象
  关联: R-03
  依赖: 无
  验证方式: ①`mvn -o -q package -DskipTests` 编译通过（贴退出码）②既有 provider 回归：默认 deepseek CHAT 跑一轮真实对话（SSE 收到 `end:true`）
  验收标准: 编译 0 错误；`HarnessModelRegistry`/`HarnessAgentFactory` 中不再以 `OpenAIChatModel` 作为字段/签名类型（`grep -c OpenAIChatModel` 归零或仅剩装配点）；既有对话行为与改动前一致
  （共享面对象 4 身份 1~4 的编译级保障）

- [x] T-02 服务端 provider 归一与 apiKey 空串处理（含 ollama 白名单）
  关联: R-01, R-02
  依赖: T-01
  验证方式: ①`POST /api/model-config/add` 传 `provider=ollama` + 空 `apiKey` → 成功（贴响应）②传非法 `provider=foo` → 被拒且提示明确 ③DB 查询该行 `api_key` 为空串（`select length(api_key)` = 0）
  验收标准: ollama 行可保存且 key 为空串；非法 provider 不落入默认分支（L-63）；装配日志含 `provider/modelConfigId/modelName/endpoint` 且**不含密钥**（日志断言）
  （共享面对象 1 身份 1/2/8）

## 2. 模型装配（三类）

- [x] T-03 Ollama CHAT / MULTIMODAL 装配与 formatter 选择
  关联: R-03, R-06
  依赖: T-02

  验收标准: 两条链路均产出回答且 `end:true`；回答内容与提示相关（非空答）；日志可据以定位是哪个 provider/模型/端点

  关联: R-07

  验收标准: 正例工具真实执行并回填结果；反例给出可诊断提示或降级行为，**无空答、无长时间挂起**（R-07 明确禁止静默失败）

  验收标准: 768 维数据成功写入并可检索（不再要求 512）；日志含维度字段
  （共享面对象 2 身份 1/2）

## 3. 模型配置面（测试 / 列表 / 维度拒绝）

- [x] T-06 Ollama 连接测试分支（三类类型）
  关联: R-04
  依赖: T-02
  验证方式: ①对 CHAT / MULTIMODAL / EMBEDDING 三条 ollama 行分别调 `POST /api/model-config/test` → 三条均"可用"（贴响应）②把 baseUrl 改为不可达端口 → 断言返回连接类错误要点
  验收标准: 三类均有测试通路；失败时可见地址/端口/模型名层面的原因（非泛化提示）；测试耗时 ≤60s

- [x] T-07 服务端代理「Ollama 模型列表」接口 + 鉴权
  关联: R-05
  依赖: T-02
  验证方式: ①调新接口 → 返回本机模型名列表（含 `gemma3:latest`/`nomic-embed-text`/`qwen2.5:7b`）②Ollama 服务不可达 → 返回失败原因（不抛 500 信封）③无 token 调该接口 → 被拒（鉴权断言，L-58）
  验收标准: 列表与 `/api/tags` 一致；失败场景前端可退化为手工输入；鉴权与既有模型配置接口同口径

- [ ] T-08 向量维度不一致显式拒绝
  关联: R-09
  依赖: T-05
  验证方式: ①构造"表为 512 维 / 当前 embedding 为 768 维"场景触发入库 → 断言被拒绝且提示含两个维度与处置建议 ②同场景触发检索 → 断言同样显式拒绝（不返回空结果）③日志断言：WARN 含期望维度/实际维度
  验收标准: 两种路径均拒绝且信息可据以处置；无静默写入/静默空结果
