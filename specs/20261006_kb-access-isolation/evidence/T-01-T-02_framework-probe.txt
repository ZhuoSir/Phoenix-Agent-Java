【实测结果（默认档）】
- 输出长度 **2391** 字；四个断言全为 true：
  `hasDomainKnowledge=true`、`hasKnowledgeDirMention=true`、`hasMemoryRecall=true`、`hasMemoryPersist=true`
- 逐字确认矛盾指引原文（与容器内会话上下文里看到的一致）：
  "## Domain Knowledge / The workspace `knowledge/` tree holds many detailed reference documents … treat that directory
   as the source of truth … injected `knowledge/KNOWLEDGE.md` (if present) plus a **full list of knowledge file paths** …"
- **结论 1（风险落地）**：Domain Knowledge 与 `## Memory Recall` / `## Memory Persistence` **由同一段输出产出**
  ⇒ `disableWorkspaceContext()`（整体关掉该 middleware）**必然连带关掉记忆指路与工作区文件提示**（不是"可能"，是同一块文本）。
- **结论 2**：`setAdditionalContextFiles(...)` 是**追加**语义（本轮输出长度不变 2391，因无附加文件可读），**不能**用来"替换/删除"矛盾段。
- **结论 3**：4 参构造 `(wm, "knowledge", "KNOWLEDGE.md", 8000)` 输出 2401 字、内容基本相同 ⇒ 它只影响注入的上下文文件名等参数，**不改变矛盾的指路本身**。
- 类结构（javap）：引导文本是**单一私有常量** `GUIDANCE_TEMPLATE`；类内**没有** legacy 变体方法
  ⇒ ② legacy 档与 ③ disable 档的行为由 **Builder** 决定，离线无法再往前推（需 runtime）。
