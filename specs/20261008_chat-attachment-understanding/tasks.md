## 3. 后端：理解与鉴权

- [ ] T-04 文档文本抽取 + 超长顺序截断告知 + 解析失败明确提示
  关联: R-05, R-08, R-09
  依赖: T-02
  验证方式: ① 五类样本（.docx/.pdf/.xlsx/.txt/.md）各含一处**独特事实**（编号/金额），
    上传后追问该事实 ⇒ 回答命中（每类一条断言）；② 超长 .pdf ⇒ 回答含「已截断」告知且
    `metadata.truncated` 落库、提问文档**末尾**事实时表明不在已处理范围（不编造）；
    ③ 加密 PDF / 损坏文件 / 无文本层扫描件 ⇒ 各自明确原因类别，**不产生空内容作答**；
    ④ 扫描件**不自动转视觉模型**（Q6 裁定）
  验收标准: 五类样本全部命中；截断告知用户可见 + 落库；三类失败各有明确提示；`extracted_chars` 有值

- [ ] T-05 附件归属鉴权 + 下载/缩略图端点
  关联: R-11
  依赖: T-02
  验证方式: 用户 A 上传后：① A 下载/取缩略图 → 200；② 用户 B 直连同一 id → **403**；
    ③ 超管 → 200（沿用 R-18 超管口径）；④ 下载响应强制 `Content-Disposition: attachment`；
    ⑤ 归属以**库中 `storage_path`** 解析，不接受请求入参拼路径（L-19）；
    ⑥ **成对实施核对**（L-58）：列表/回看与单对象端点同批具备校验，缺一即不合格
  验收标准: 三身份各一条断言全过；无越权读取；无内联 HTML 回显

- [ ] T-06 stream 集成 `attachmentIds` + 图片多模态装配 + 降级显式告知 + metadata 标注
  关联: R-06, R-07, R-10
  依赖: T-03, T-04, T-05
  验证方式: ① **对面断言 S1**：**不带** `attachmentIds` 的既有 stream 调用行为不变
    （同一 agent 同一提示词，事件序列与改动前一致）；② 带图片附件 ⇒ 走 MULTIMODAL 且回答反映图片内容；
    ③ 临时停用 MULTIMODAL 行 ⇒ **降级**且回答含「图片未被理解…仅根据文本作答」、
    `metadata.attachmentNotice` 落库、**重开历史会话仍见该标注**；④ 只发图片问「图里是什么」⇒
    明确说明无法理解图片、**不编造**；⑤ **对面断言 S6**：改动前的旧消息（metadata 无新键）渲染不报错；
    ⑥ 发送后附件回填 `message_id`
  验收标准: 六条断言全过；降级路径不出现"假装看过图"的表述
