# 需求：智能体配置 AI 生成（描述/Prompt）+ Prompt Markdown 编辑 + 模型「启用集合 / 默认模型」

## 背景与目标

新建智能体时，管理员要先起名字，再手写「描述」和「提示词」——三者强相关，手写慢且质量不一；而提示词本身是结构化文本（角色、能力、边界），用纯文本框写既难维护也容易漏项。系统已具备对话模型调用能力与 Markdown 渲染能力，可以：① 基于名称代拟描述与**结构化 Markdown 提示词**；② 让提示词用 Markdown 方式编辑。

本需求四件事：
1. **智能体配置**（管理端编辑抽屉「基本信息」区）提供「AI 生成」：以已填**名称**为输入，调模型生成**描述**与**提示词**回填表单，人工确认后随保存落库。
2. **提示词支持 Markdown 编辑**：可直接书写 md 语法并预览；生成产物同样是 md，且带固定骨架（角色 / 描述 / 能力 / 安全范围 等）。
3. **模型管理引入两个独立概念**：**启用**（现有字段，语义变更）= 同类型允许多个启用，构成"可被选择的模型集合"；**默认**（新增字段）= 每类型至多一个，"没被显式选择时的加载项"。
4. 生成能力使用 **CHAT 默认模型**；三种类型（CHAT / EMBEDDING / AUDIO）**都要**默认标记。

成功长什么样：输入名称点一下，几秒内拿到中文描述 + 一段带「角色/描述/能力/安全范围」的 Markdown 提示词，可在 md 编辑器里继续改并实时预览；模型管理可启用多个模型供智能体挑选，不挑时按默认加载；换默认后再生成/加载立刻跟随；没有可用默认时给出明确引导而不是空转。

## 需求条款

### 一、生成能力
- **R-01** WHEN 管理员在智能体编辑界面（新建或编辑）已填写名称并触发「AI 生成」, 系统 SHALL 以名称（可携带已填描述/提示词作为上下文）调用**默认 CHAT 模型**，生成**描述**与**提示词**两项文本回填表单，且**不自动保存**智能体。
- **R-02** WHERE 生成结果落在表单, 系统 SHALL 允许保存前编辑、撤销（恢复点击前内容）或改用手工输入。
- **R-03** WHEN 管理员只对「描述」或只对「提示词」触发单项生成, 系统 SHALL 支持单项生成，两项的成功/失败/进行中状态互不牵连。
- **R-04** WHEN 生成结果将覆盖字段中**已有的非空内容**, 系统 SHALL 先弹出确认，管理员取消则保留原内容、不写入生成结果。

### 二、提示词的 Markdown 形态
- **R-05** WHEN 管理员编辑智能体「提示词」, 系统 SHALL 提供 **Markdown 编辑方式**：可直接书写 md 语法（标题、列表、粗体、代码块、表格、引用等），并提供**实时预览**（或源码/预览切换）。
- **R-06** WHEN 「AI 生成」产出提示词, 系统 SHALL 返回 **Markdown 语法文本**，且 SHALL 至少包含固定骨架段落：**角色、描述、能力、安全范围**（可按名称语义追加如输出要求、工具使用规范等段落），内容为中文、非空标题占位（不留 `TODO`/空段落）。
- **R-07** WHERE 提示词以纯文本存入**现有 `prompt` 字段**：引入编辑器与 md 语法 SHALL NOT 改变存储形态与下发方式（保存的是 md 原文，运行时按原文作为系统提示词下发，渲染发生在编辑/预览侧）。
- **R-08** WHEN 提示词为空, 系统 SHALL 提供「插入 Markdown 骨架」入口：一键填入含上述固定段落的模板，使手工填写也具备同样结构。
- **R-09** WHERE 「描述」字段仍为纯文本（单段说明），本需求的 md 编辑与 md 生成 SHALL 仅作用于**提示词**。

### 三、模型管理：启用与默认
- **R-10** WHEN 管理员启用或停用某个模型配置, 系统 SHALL 允许**同一类型存在多个启用配置**（取消原"同类型唯一启用"的互斥行为），启用集合即"可被选择的模型"来源。
- **R-11** WHEN 管理员把某配置设为其类型的**默认模型**, 系统 SHALL 保证**每个类型至多一个默认**（设新默认自动取消同类型旧默认），且默认标记在列表中**可见可辨**。
- **R-12** WHEN 某配置被设为默认, 系统 SHALL 保证该配置同时处于**启用**状态（设为默认即启用）。
- **R-13** IF 管理员试图停用某配置，而它是该类型当前默认, 系统 SHALL 阻止并给出明确提示（需先改默认，或一并取消默认）。
- **R-14** WHERE CHAT / EMBEDDING / AUDIO **三种类型**均支持默认标记, 各自独立（CHAT 的默认不影响 EMBEDDING 的默认）。

### 四、运行时取模型的规则
- **R-15** WHERE 智能体运行配置**未选择**对话模型, 系统 SHALL 加载 **CHAT 默认模型**；已选择时 SHALL 使用所选配置。
- **R-16** WHERE 智能体运行配置的**模型下拉选项**仅来自"该类型启用集合"；已保存的选择若后来被停用，系统 SHALL 在生成/对话时按**默认模型回退**并给出可诊断的提示日志（不静默使用不可用模型）。
- **R-17** WHERE 平台内既有的、按类型取模型的能力（嵌入向量化、语音等）, 系统 SHALL 改为取**该类型默认模型**；换默认后新发起的向量化/推理 SHALL 使用新默认（存量向量不因换默认而自动重算）。
- **R-18** IF 某类型不存在可用默认模型（未设置，或所指向配置已删除/停用/无法解析）, 系统 SHALL 对该能力的调用返回**可展示的明确提示**（引导去模型管理设置），不写入半成品结果、不清空用户已填内容、不使既有保存流程失败。

### 五、兼容与升级
- **R-19** WHERE 本需求产生库表变更（模型配置新增默认标记列）, 升级件 SHALL 幂等可重放；**存量回填**规则：每个类型把"当前唯一启用"的那条回填为该类型默认（该类型无启用项则回填最新一条；一条都没有则不设默认）。
- **R-20** IF 执行回滚件, 系统 SHALL 移除新增的默认标记列且**不影响启用列与既有数据**（回滚后行为退回需求前版本）。
- **R-21** WHERE 存量智能体的 `prompt` 已是纯文本, 系统 SHALL 正常展示与运行（编辑器按普通 md 源码加载，不强制改写历史内容）。

## 验收场景

- **AC-01（R-01/R-15）** GIVEN 已设 CHAT 默认；WHEN 输入名称「合同审查助手」点「AI 生成」；THEN 数秒内描述与提示词被填入，未保存不写库；日志显示所用为默认 CHAT 配置（模型名/配置ID）。
- **AC-02（R-06/R-07）** GIVEN 生成完成；WHEN 查看提示词；THEN 内容是 Markdown（含 `## 角色`、`## 描述`、`## 能力`、`## 安全范围` 四段且各有实际内容），预览可正常渲染标题/列表/代码块。
- **AC-03（R-04）** GIVEN 提示词已有手写内容；WHEN 生成完成；THEN 弹确认，取消后原文保留。
- **AC-04（R-03）** GIVEN 一次生成中提示词失败而描述成功；THEN 描述已回填、提示词显示失败原因并可单独重试。
- **AC-05（R-05/R-08）** GIVEN 提示词为空；WHEN 点「插入 Markdown 骨架」；THEN 填入四段模板且可继续编辑；WHEN 手工输入含 `**加粗**` 的文本并保存；THEN 原文保存、预览正确。
- **AC-06（R-10）** GIVEN 两个 CHAT 配置；WHEN 依次启用两者；THEN 两者同时为启用态（原互斥不再发生），都不被自动停用。
- **AC-07（R-11/R-14）** GIVEN CHAT 默认=A；WHEN 把 B 设为默认；THEN 默认唯一落在 B、A 的默认取消，且 A/B 的**启用状态不受影响**；EMBEDDING 的默认保持原值。
- **AC-08（R-12/R-13）** GIVEN 某 EMBEDDING 配置未启用；WHEN 设为默认；THEN 该配置自动启用。WHEN 再试图停用这条默认；THEN 被阻止并提示。
- **AC-09（R-16）** GIVEN 智能体选了模型 X；WHEN X 被停用（且非默认）；THEN 对话与生成按默认回退，日志有「所选模型已停用，回退默认」提示。
- **AC-10（R-17）** GIVEN 换 EMBEDDING 默认后；WHEN 重新做数据源 schema 初始化；THEN 新向量使用新默认模型；失败时返回可读信息。
- **AC-11（R-18）** GIVEN 某类型无默认；WHEN 触发 AI 生成/依赖该类型的操作；THEN 返回明确引导文案，表单内容不变。
- **AC-12（R-19/R-20）** 空库与存量库各跑一遍升级件：默认列存在、每类型恰好一个默认（按回填规则）；重复执行零报错；执行回滚件后默认列消失，启用列与数据无变化。
- **AC-13（R-21）** GIVEN 存量智能体 prompt 为纯文本；WHEN 打开编辑器；THEN 正常加载为 md 源码、预览不报错，保存后内容不变（不被强改）。

## Non-goals（范围外）

- 不生成名称、分类、头像、预设问题、知识库/数据源等非文本配置。
- **描述**字段不做 md 编辑器（仍纯文本单段）。
- 不做所见即所得富文本双模编辑（如 word 式排版）、不做图片/附件插入、不做 md → PDF/Word 导出、不做版本对比。
- 不做多候选生成、生成历史、生成话术（meta-prompt）的可视化编辑或租户级定制（骨架段落集合固定，内置话术不做管理界面）。
- 不新增模型接入方式、不做模型可用性探测/自动健康检查（沿用现有「测试连接」）。
- 不因换默认而自动重算历史向量数据。
- 不改智能体「运行配置」面板整体结构与技能配置逻辑（仅模型选项来源与回退规则变化）。
- 不做前台/普通用户的生成入口（仅管理端）。

## 我正在做的假设

- **A-01**（已确认）启用与默认**互相独立**：启用=可被选择的集合（可多个），默认=未选择时的加载项（每类型唯一）。
- **A-02**（已确认）CHAT / EMBEDDING / AUDIO 三种类型**都要**默认标记，各自独立。
- **A-03**（已确认）覆盖已有内容前**弹确认**。
- **A-04**（已确认）提示词走 **Markdown**：可直接写 md 语法 + 预览；生成产物为 md 且含**角色/描述/能力/安全范围**骨架。
- **A-05** 默认标记是**新列**（不改 `is_active` 列本身），仅其互斥行为被取消（R-10）。
- **A-06** 生成参数：中文；描述一句话（≤120 字）、提示词 md 约 300~600 字；同步返回（非流式），超时约 60s（生成 md 提示词比纯文本更耗时）；一次一条。
- **A-07** 入口位置：编辑抽屉「基本信息」区（名称/描述/提示词同屏）与 `/agent/:id` 编辑页一致；新建未保存时也可生成。
- **A-08** 生成**始终**用 CHAT 默认，不受"某智能体自己选的模型"影响。
- **A-09** 运行时行为：md 原文即系统提示词（模型能理解 md，无需转换）；与现有「显式技能注入」的系统提示拼接不冲突（追加而非改写）。
- **A-10** 仅管理端可用，沿用 `/api/**` 登录鉴权；错误按项目 `ApiResponse`/`ReturnVo` 约定返回。
