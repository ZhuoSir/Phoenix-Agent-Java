# 任务清单：交付链加固（release-delivery-hardening）

> 覆盖关系：R-01→T-05/T-10｜R-02→T-03/T-04/T-10｜R-03→T-02/T-10｜R-04→T-06/T-10｜R-05→T-07/T-08/T-10
> 共享面任务（T-01/T-02/T-06/T-08）的验证方式内含 plan「共享面身份矩阵」各既有身份的对照断言。

## 1. 基础与前置能力（R-03）

- [x] T-01 `lib/common.sh` 增量新增底座/引擎/门禁通用函数（不修改既有函数签名与输出格式）
  关联: R-01, R-02, R-05
  依赖: 无
  验证方式: ① `sh -n` 语法检查；② **身份对照（common.sh 4 个既有调用方零回归）**：`bootstrap.sh`/`install.sh`/`package.sh`/`verify.sh` 各跑一次空转或 `--help` 路径，比对改动前后退出码与首屏输出；③ 新增函数的单元自测（临时脚本调用，断言返回值/日志格式）
  验收标准: 4 个调用方在改动前后行为无差异（退出码 + 关键输出一致），新增函数自测通过；无 `printStackTrace`/裸 `echo` 混入日志

- [x] T-02 `install.sh` 步骤 1 前置能力闸：`OSType=linux` + `docker context ls` + Compose v2（含插件系统级/用户级路径探测；删除现有 v1 回退分支）
  关联: R-03
  依赖: T-01
  验证方式: ① **反例**：用 PATH shim 造"仅 v1、无 v2 插件"环境跑 `install.sh` → 断言在步骤 6 之前失败、退出码非 0、`docker ps -a` 无本项目容器；② **正例**：本机 v2 环境跑 → 正常进入步骤 2；③ **身份对照（install.sh 6 身份）**：全新安装 / 重跑幂等 / `--env-from` / `--offline` / `--from-wsl` / `PHOENIX_ALLOW_ARCH_MISMATCH=1` 各一条断言，确认能力充足时行为不变；④ `OSType=windows` 模拟路径断言被拒
  验收标准: 反例/正例输出与退出码符合预期；6 身份中 5 个在本机可执行的身份行为与改动前一致；日志断言：拒绝时出现 ERROR 行含"检测到的能力 + 所需能力 + 指引 + 已创建容器数=0"

## 2. 离线引擎件（R-02）

- [x] T-03 打包侧：`package.sh` 支持 `--engine-tgz <本地路径|URL>`，将静态二进制落入 payload 的 `engine/docker-<ver>-<arch>.tgz` 并生成 `sha256`；入包前按 sha256 + 字节数对账
  关联: R-02
  依赖: T-01
  验证方式: ① 用本地 tgz 跑一次打包 → `ls` + `sha256sum -c` + 字节数与源文件一致；② 用**故意截断**的 tgz 触发对账失败 → 断言拒绝入包并非 0 退出；③ 外部 URL 逐条列出并标注可达性（L-71）
  验收标准: 正常件入包且校验通过；截断件被拒；日志含"来源 / 架构 / 版本 / 字节数 / sha256"

- [x] T-04 `install.sh` 步骤 2 离线引擎落地：解包静态二进制 → `/usr/local/bin`，配 systemd unit（无 systemd 降级 `nohup` 并显式告知）；已有 Docker 则幂等跳过；架构不匹配即停止
  关联: R-02
  依赖: T-01, T-03
  验证方式: ① 在**无 Docker 的 Debian 容器**（`--privileged` 且明确记录该限制）中执行步骤 2 路径 → 断言 `docker version` 可用、自启配置存在或显式降级告知；② 本机（已有 Docker）执行 → 断言跳过且不重复安装；③ 塞入异构架构 tgz → 断言明确报错停止；④ 日志断言：INFO 含来源/架构/版本；ERROR 含缺失项与手工指引
  验收标准: 三场景输出符合预期；**如实记录容器内验证的局限**（非真实 systemd 环境需在目标机补验，未验即标注"未验证"）

## 3. 底座与差异记录（R-01）

- [x] T-05 `package.sh` 底座选择与差异记录：支持 `--base-image`；`manifest.json` 增 `base_images`（逐架构）与 `equivalence_note`；替代底座时打印显式 WARN
  关联: R-01
  依赖: T-01
  验证方式: ① 正常路径跑打包 → `jq` 读取 manifest 断言 `base_images.arm64/amd64` 字段存在且一致；② 模拟底座不可得（指定不存在镜像）→ 断言走替代分支、manifest 含差异记录、流程**成功产出**且 WARN 可见；③ 镜像摘要/字节对账（L-73）
  验收标准: 两情形产物齐备、manifest 字段可被逐项核对；差异记录含"架构↔底座↔`JAVA_BIN` 语义↔影响"四项

## 4. 维度迁移独立脚本（R-04）

- [x] T-06 新增 `docker/scripts/vector-dim-migrate.sh`（`--dims N [--dry-run] [--pg-container NAME] [--table T]`）：删索引时排除约束承载索引；迁移后自检维度与 id 唯一约束，不通过即给修复语句
  关联: R-04
  依赖: T-01
  验证方式: ① 在独立 pgvector 库跑 `--dry-run`（事务回滚）→ 断言数据未变（维度/行数/约束数与执行前一致）；② 真跑一次 → 断言 4 表维度=目标值、hnsw 索引已重建、**约束数不减**；③ **反例**：造"缺 PK"表 → 断言自检报出并打印 `ADD CONSTRAINT ... PRIMARY KEY (id)`；④ **反例**：造重复 id → 断言报重复组数并给查重/去重语句；⑤ **身份对照（向量表 3 身份）**：平台写入路径（入库一篇文档）+ 检索路径（检索命中）+ 运维脚本，三者仍正常；⑥ 日志断言：逐表 INFO（表名/原维度/目标维度/索引动作/行数）+ 自检结果
  验收标准: 五类场景实测输出齐备；迁移前后约束数对账记录留档

## 5. 出货门禁（R-05）

- [x] T-07 新增 `docker/scripts/gate.sh`：门禁前环境体检三件套 + 四项自检（全新空库安装 / 容器内 jar 可读 / `.sha256` 可校验 / 前置声明与实测一致），证据落盘
  关联: R-05
  依赖: T-01, T-04
  验证方式: ① **反例甲**：镜像内 jar 权限 0600 → 断言门禁 FAIL 且日志指出该失败项与复现命令；② **反例乙**：故意写坏 `.sha256` → 断言 FAIL；③ **正例**：正常包四项全 PASS → 退出码 0，证据目录含四项真实命令输出；④ 门禁用**独立项目名 + 独立端口**，断言结束后 `docker ps -a` 无该项目残留、现网栈未受影响（L-04/L-97）；⑤ 日志断言：开始/结束 INFO 含 `runId/版本/架构/四项结果/耗时/退出码`
  验收标准: 两反例 + 一正例实测输出齐备；证据目录可复核；环境体检结果随失败输出

- [x] T-08 `package.sh` 出货步骤强制调用 `gate.sh`；`--skip-gate` 仅调试（显式 WARN）；门禁通过后**复核包哈希**并与出货记录绑定
  关联: R-05
  依赖: T-07
  验证方式: ① 默认出货 → 断言门禁被执行，门禁失败时 `package.sh` 非 0 退出且不产出"已出货"结论；② 带 `--skip-gate` → 断言打印"非出货用途"WARN；③ 门禁后改动一个 payload 文件 → 断言哈希复核发现不一致并拒绝出货；④ **身份对照（package.sh 6 身份）**：arm64 / amd64 / `--mirror` / `--version` / `--out` / 断点续跑（state 文件）各一条断言
  验收标准: 三场景 + 6 身份断言通过；出货记录含包哈希与门禁证据路径
