# 需求规格：对话智能体统一化与去硬编码（dynamic-agent-types）

## 术语
- **对话智能体**：本需求唯一面向用户呈现的智能体形态，支持 **Skill（技能）** 与 **Tool（工具）**。技术实现沿用现有 Harness 运行时，库中 `type` 值**保留 `harness`**（不迁移存量数据）；对外文案、菜单、列表、按钮一律称「对话智能体」，**不再出现「数据智能体 / 智能体 / 流程智能体 / Harness」这四个标签**。

## 背景与目标
现状（2026-09-27 实测，bugs.md B-10 / profile）：
- 库中 7 个智能体里 **5 个由 Java 类启动自注册**并在运行时按 **sn** 取内存实例：`BpmReactAgent`、`ZhiduReactAgent`（type=agent）、`ParolCompiledGraph`（type=workflow）、`RulesHarnessAgent`、`HumanInTheLoop`（type=harness）
- 后台「新建智能体」不传 `type` → 落库 NULL、**无任何运行时**；`sql` 按 agentId 走 NL2SQL 状态图（唯一后台可建可用者）
- 前端存在**四类类型标签**（`sql/agent/workflow/harness`）与类型筛选，但四类能力高度重叠、且其中三类无法后台创建 → 概念混乱
- **技能（Skill）仅对 harness 运行时生效**；知识库检索工具（`RulesRagTool.getRagInfo`）只挂在硬编码的制度专家上；**数据库查询未接任何工具**（平台有 `Nl2SqlService` 与自带 MCP 工具可复用）

**方向（2026-09-27 用户拍板）**：以 Harness 运行时**统一承载**「对话 + 知识库 + 数据库查询 + 技能 + 工具」，对外只叫**对话智能体**；前端**去掉四个类型标签**、新建不再要求选择类型；`agent`/`sql`/`workflow` 存量智能体代码与数据**保留可用**（作实现参考，本期不迁移不删除）；MCP 与工作流编排**列入待办**（`specs/_project/backlog.md` BL-01/BL-02）。

## 需求条款

### R-01 类型概念下线（界面上只有「对话智能体」）
后台智能体**列表 SHALL NOT 展示类型列/类型徽标**，SHALL NOT 提供类型筛选；新建智能体 SHALL NOT 要求选择类型（一律创建为对话智能体）。
系统 SHALL NOT 在任何用户可见文案中出现「数据智能体 / 智能体 / 流程智能体 / Harness」这四个标签。
IF 存量智能体（`sql`/`agent`/`workflow`）出现在列表中, THEN 系统 SHALL 仅展示名称/描述/状态等业务信息，不展示其类型。

### R-02 新建智能体不依赖 Java 自注册
新建智能体 SHALL 完全由库配置驱动其运行时构建与寻址；SHALL NOT 依赖 `SmartInitializingSingleton` 自注册或按 sn 的静态加载器。
存量 5 个 Java 自注册智能体 SHALL **保留原样**（实现参考与兜底，本期不删除、不迁移），其存在 SHALL NOT 成为新能力的必要前提。

### R-03 对话智能体数据驱动创建
WHEN 用户新建或编辑对话智能体, 系统 SHALL 以库配置构建运行时：系统提示词、模型（取自模型配置）、**技能仓库**、**工具集**、记忆、计划模式开关、文件系统策略。
WHEN 发起对话（后台运行页 / 前台对话）, 系统 SHALL 以 **agentId** 即时构建或取得该智能体实例。

### R-04 工具：知识库
WHEN 新建或编辑对话智能体, 系统 SHALL 允许开启「知识库检索」工具并可配置其作用范围（复用现有向量/知识检索能力语义）。
WHEN 对话中需要知识检索, 系统 SHALL 由该工具返回知识库内容。

### R-05 工具：数据库查询（两级）
WHEN 新建或编辑对话智能体, 系统 SHALL 允许开启数据库查询能力并选择目标数据源，含两个独立工具：
- **取数工具（默认开）**：自然语言 → SQL → 结果；只读、限定所选数据源
- **深度分析工具**：内部复用既有 NL2SQL 状态图能力（多步规划 / SQL 执行 / Python 深度分析 / 报告 / 人工反馈）
IF 两个工具都未开启, THEN 界面 SHALL 提示"该智能体不具备数据库查询能力"（不静默）；IF 数据源未配置或不可达, THEN 工具调用 SHALL 返回明确错误。

### R-06 存量智能体保持可用
存量 `sql`/`agent`/`workflow` 智能体 SHALL 保持现有对话/执行行为可用（SHALL NOT 因本需求失效）；其数据源、知识、技能绑定、会话 SHALL NOT 丢失。
（说明：仅"类型标签"在界面上消失，功能不变。）

### R-07 工作流与 MCP 不在本期
工作流图定义与可视化编排、MCP 工具接入 SHALL NOT 在本期实现，已登记 `specs/_project/backlog.md`（BL-02 / BL-01）。
存量 `workflow` 智能体本期仍按原路径可用。

### R-08 寻址统一
所有对话通道 SHALL 以 **agentId** 寻址智能体；`sn` 仅保留兼容与展示用途（移除 `agent.sn || agent.id` 之类兜底写法）。
IF agentId 不存在或无可用运行时, THEN 系统 SHALL 返回明确错误码与提示，SHALL NOT 泄漏 `NoSuchElementException` 等内部异常。

### R-09 前端配置面板
后台编辑抽屉 SHALL 以「对话智能体」的配置面呈现：系统提示词 / 模型 / 技能配置（复用既有 AgentSkillConfig）/ 知识库工具 / 数据库查询工具（两级开关 + 数据源）/ 计划模式。
存量智能体编辑时沿用其原有面板（数据源/知识/语义等），不新增类型相关文案。

### R-10 权限与可见性
组授权可见性（`getMyAgents`）、后台菜单 ACL、前台技能区（`specs/20260927_agent-skill-management` R-09）语义 SHALL 保持与本需求前一致；本需求不引入新权限模型。

### R-11 兼容与回滚
本需求产生的库表/配置变更 SHALL 提供升级与回滚脚本并登记 artifacts.md（先加后删原则）；SHALL NOT 破坏存量智能体与既有升级件（01/02 两个脚本）的可重放性。

## Non-goals（范围外）
- **MCP 工具接入**（BL-01）与**工作流编排**（BL-02）——待办，另行立项
- 存量 Java 自注册类与存量类型数据的删除/迁移
- 工具集的自定义脚本/DSL 注册（本期仅内置工具开关）
- 多智能体协作/子智能体编排（AgentScope Subagent）
- 前台创建智能体（仍限后台）
- `type` 字段的数据库值改名（保留 `sql/agent/workflow/harness` 原值，仅去掉**展示标签**）

## 我正在做的假设
1. 模型统一取自既有「模型配置」（modelconf），不在智能体上冗余存密钥。
2. 对话智能体运行时复用现有 `HarnessAgent.builder()` 能力面，去掉"必须由 Java @Component 提供"这一层；`type` 值沿用 `harness`。
3. 知识库工具复用现有 RAG 工具语义，可泛化为按智能体配置作用范围。
4. 数据库取数工具以「数据源 + 只读」为前提；写操作不在本期。
5. 存量 5 个自注册智能体继续按原路径工作（双轨并存），新增一律走数据驱动。
6. 前台对话沿用 `specs/20260927_agent-skill-management` 交付的 `/platform/harness/chat`（含技能显式执行与三重校验）。
7. 去掉类型标签后，存量 `sql`/`agent` 智能体在**运行页**的设备/通道选择仍按其实际能力自动判定（用户无需理解类型）。

现在纠正，否则按此执行。
