# 任务清单：超长文档分批处理（long-doc-chunking）

> 覆盖检查：R-01~R-10 均有任务覆盖（见各任务「关联」）。
> 共享面断言：T-02（extractor 两个调用方）、T-09（prepare 三条链路）、T-10（端到端）。
> 日志断言：T-04/T-06/T-07/T-08 覆盖 plan §八 六条日志点。

## 组 1 · 基础能力

- [x] T-01 新增 6 个配置项并把 `MAX_EXTRACT_CHARS` 改为配置驱动
  关联: R-05, R-10
  依赖: （无）
  验证方式: 启动时日志打印 6 项生效值；改 env（`PHOENIX_AGENT_CHAT_ATTACHMENT_CHUNK_SIZE=4000`）重启后断言日志值变化；
    断言代码中不再有硬编码 24000（`grep` 计数 0，常量改为 DEFAULT_ 前缀仅供默认值引用）。
  验收标准: 6 项均可配、生效值可在日志核对；无残留硬编码。

- [x] T-02 `ChatDocumentExtractor` 返回全文 + 安全上限（2M）
  关联: R-03, R-05
  依赖: T-01
  验证方式: 用 3 万字 docx 抽取，断言 `text.length=30000` 且 `truncated=false`；
    构造 2.1M 字符文本，断言 `truncated=true` 且文案含实际安全上限值；
    回归两个调用方（装配器、上传服务）不报错（日志无异常）。
  验收标准: 三条断言全过并贴输出；上传服务提示文案与配置值一致。

## 组 2 · 切片与批处理

- [ ] T-03 `DocumentChunker` 语义切片
  关联: R-01
  依赖: T-02
  验证方式: 三类样本（①无标题超长段落 ②多级标题文档 ③中英混排）各跑一次，断言：
    每块 ≤6000、块间 overlap=300、切点落在段落/标题边界（不出现半句），块数符合预期。
  验收标准: 3 类样本断言全过；切片函数有单元测试或可复现脚本记录。

- [ ] T-04 `DocumentBatchProcessor`：map（要点+关键原文摘录）→ reduce（按章节聚合）
  关联: R-02, R-03
  依赖: T-03
  验证方式: 用 3 批规模文档跑真模型，断言 reduce 输出包含各批的关键摘录句子；
    日志断言：`[doc-batch] 开始 attachmentId=… chars=… chunkCount=3` 与
    `[doc-batch] 结束 … processed=3 degraded=false totalMs=…` 各出现 1 次。
  验收标准: 输出含各批关键句 + 两条日志齐全。

- [ ] T-05 进度帧下发（「正在处理第 x/N 批」+ 结束标注）
  关联: R-04
  依赖: T-04
  验证方式: 真栈 SSE 抓包（`curl -N`）断言帧序列含 `notice` 的 `第 1/N 批`…`第 N/N 批` 与结束文案
    「共 N 批，已全部处理」；断言 `content` 字段未被进度污染。
  验收标准: 进度帧序列完整且不污染正文。

## 组 3 · 护栏、失败与幂等

- [ ] T-06 护栏与摘要降级（批数 >20 / 累计 >20000 字）
  关联: R-06, R-07
  依赖: T-04
  验证方式: 构造 50 万字文档，断言：停止条件在第 20 批或预算处触发；
    提示文案含「已按摘要方式处理（覆盖前 N 批约 X%）」；日志 `[doc-batch] 降级 … reason=…` 出现 1 次；
    断言回复中**不出现**「已全部处理」。
  验收标准: 四条断言全过，文案不撒谎。

- [ ] T-07 单批失败重试与范围说明
  关联: R-08
  依赖: T-04
  验证方式: 用可失败 mock（某批返回 500）跑一次，断言：重试 1 次（日志 WARN 含 `attempt=2`）；
    仍失败则该批跳过，最终提示含「第 x 批处理失败，其余 N-1 批已完成」。
  验收标准: 重试日志 + 提示文案均可复现。

- [ ] T-08 幂等去重 + 六条日志点落地
  关联: R-09
  依赖: T-04
  验证方式: 同一轮内触发两次装配，断言 `[doc-batch] 开始` 只出现 1 次（去重生效）；
    逐条核对 plan §八 六条日志（开始/单批完成/失败重试/降级/结束/安全上限截断）均能触发。
  验收标准: 去重断言 + 六条日志逐条有证据。

## 组 4 · 接入与端到端

- [ ] T-09 装配器接入 + 三链路生效 + 未超阈值行为不变
  关联: R-02, R-10
  依赖: T-02, T-04, T-05
  验证方式: ①5000 字文档：断言**无**分批（无 `[doc-batch] 开始` 日志、无进度帧），与改动前行为一致；
    ②3 万字文档：分别走后台 `/api/admin/harness/chat`、前台 `/api/front/harness/chat`、confirm 续跑，
    断言三条链路都有进度帧与降级/完成标注（按需构造）。
  验收标准: 小文档零变化；三条链路都触发分批。

- [ ] T-10 端到端验收（5 万字 docx 问"第 4 章第 3 条"）
  关联: R-03, R-04
  依赖: T-05, T-06, T-07, T-08, T-09
  验证方式: 造一份 5 万字 docx（第 4 章第 3 条内容放在**原 24000 字符之后**）→ 上传 → 提问 →
    断言回答包含该条内容（证明后半段参与理解）+ 有进度帧 + 有结束标注；保留日志与回答原文。
  验收标准: 回答命中后半段内容（关键句逐字比对），三条证据齐全。
