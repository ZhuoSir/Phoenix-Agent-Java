# 需求规格：向量维度灵活化（vector-dim-flexibility）

## 背景与目标

平台当前的向量维度是**表级硬编码**：`embedding` 列声明为 `vector(512/768/1024)`，换 embedding 模型必须
停服做 DDL + 清空 + 重新嵌入（本日现场即因此踩坑：BUG-195 缺唯一约束、四张表必须一起改、R-09 全表校验拒绝写入）。
BL-61 目标是让维度成为**可配置能力**，从而兼容更多向量模型（512/768/1024/1536/2048…）。

**成功长什么样（待随路线选择细化）**：换 embedding 模型时，**不需要人工写 DDL**、不需要手工清库；
平台能给出受控的切换流程（含备份、进度、校验、回滚），且新旧模型可按需并存或平滑替换。

## 需求条款（草稿：待"目标形态"拍板后定稿）

> 本节暂留空。目标形态（受控迁移 / 每库绑定模型 / 无 typmod+dims 列 等）是 R 条款的前提，
> 见文末「待确认问题 Q1」。

## Non-goals（范围外）

- 不做 embedding 模型微调/训练
- 不做跨模型的向量相似度比较（不同模型向量空间不可比，只做"各用各的"）
- 不做检索算法替换（仍为 hnsw + cosine）

## 我正在做的假设

1. 现有 4 张向量表（rag / simple_data / user_memory / harness knowledge）为唯一向量存储面
2. 换模型的驱动力来自现场部署（内网模型维度与平台默认不一致）
3. 允许短暂的写入停写窗口（分钟级），但要求**可回滚**与**进度可见**

现在纠正，否则按此执行。

## 待确认问题

- **Q1（阻塞，需拍板）**：**目标形态**选哪条？
  - **A 受控迁移**：不改表结构策略（列仍锁维度），但把"换模型→改列→重嵌"做成**平台内受控任务**
  - **E 每库绑定模型**：一个知识库绑定一个 embedding 模型，多模型并存（终局形态）
  - **D 无 typmod + `dims` 列**：`embedding vector`（不锁维度）+ 行级 dims + 按维度部分索引（最灵活、改动最大）
  - 建议：**A → 中期 E**（A 先消除手工 DDL 风险，E 才是"兼容更多模型"的正解）
- **Q2**：切换时必须**重新嵌入**（旧向量作废）——是否接受"旧向量保留窗口 + 可回滚到旧模型"的代价（磁盘/时间）？
- **Q3**：是否需要**多模型并存期**（同一库同时持有两套向量以支持灰度对比）？
