## 1. 绑定与建库（R-01 / R-06）

- [x] T-01 数据模型与迁移件：`tbl_data_knowledge_base` 增 `embedding_model_id`/`model_space_key`（幂等 `ALTER TABLE IF EXISTS`）+ 存量回填规则 + 基线 SQL 同步
  关联: R-01, R-06
  依赖: 无
  验证方式: ①**全新库**跑基线 SQL；②**存量库**跑升级件（回填：能判定生成模型的写回该模型，不能判定的标记"待重建"）；③幂等重跑升级件（0 错误、0 变更）；④列名/类型核对 `\d`
  验收标准: 两条路径均通过；回填规则可核对（贴出回填前后计数）；幂等重跑无副作用；基线可重放（L-49/L-53）

- [x] T-02 知识库创建/编辑选择向量模型（创建默认=默认模型、可手动改选；编辑换模型 ⇒ 返回"将重建"提示，不直接生效）
  关联: R-01
  依赖: T-01
  验证方式: ①创建时不传模型 ⇒ 绑定默认模型；②创建时传 B ⇒ 绑定 B；③创建后改平台默认 ⇒ 该库绑定不变；④编辑换模型 ⇒ 返回提示且向量未变；⑤**身份对照（知识库 CRUD 4 身份）**：创建 / 编辑 / 列表与详情 / 作为检索范围过滤 各一条断言
  验收标准: 5 组断言通过；绑定值在详情接口可见；换模型提示文案含"将重建"

- [x] T-03 前端知识库表单"向量模型"下拉（默认选中默认模型、可改选；编辑态显示当前绑定与更换提示）
  关联: R-01
  依赖: T-02
  验证方式: ①打开创建表单 ⇒ 默认选中默认模型；②改选并保存 ⇒ 详情显示所选模型；③编辑态更换 ⇒ 出现"将重建"提示；④边界：无可用模型时下拉禁用并提示
  验收标准: 四场景人工/接口实测通过；提示文案与后端返回一致

## 2. 模型→表映射与归属（R-02 / R-06）

- [x] T-04 每模型一套向量表：按 `<原表名>__<模型键短哈希>` 建表（列保留该模型确定维度 + hnsw 索引）、按"库→模型→表"装配向量存储实例
  关联: R-02, R-06
  依赖: T-01
  验证方式: ①新增模型 B ⇒ 只创建 B 的表与索引，A 表的行数/维度/索引定义**逐项不变**；②**身份对照（向量表 4 身份）**：写入路径 / 检索路径 / 运维脚本 / harness 存储 各一条断言仍正常；③**身份对照（PgVectorStore 装配 4 身份）**：rag / simple / memory / harness 四个 store 在**单模型部署**下解析到的表与改动前**同一张**（等价性）；④建表脚本幂等重跑
  验收标准: 隔离性 + 单模型等价性 + 8 条身份断言通过；建表日志含模型键/表名/维度

- [x] T-05 向量归属记录与体检数据源：写入时落向量空间键与知识库归属；提供按库的归属可见（模型/空间键/规模/最近重建时间/可用性）
  关联: R-06
  依赖: T-04
  验证方式: ①写入后按库可查到空间键；②桩一个"不可达模型" ⇒ 体检输出列出其绑定的库与规模；③**边界**：绑定为空串时按 L-76 语义处理（不回落默认）
  验收标准: 归属可查、体检输出正确、空串边界用例通过

## 3. 按库检索与扇出（R-03）

- [x] T-06 单库按绑定模型检索（检索链路从"平台默认模型"改为"该库绑定模型"）
  关联: R-03
  依赖: T-04
  验证方式: ①单模型部署下，用**同一批历史数据**对比改动前后 top-k 命中（集合一致或更优，L-27 存量态回归）；②**身份对照（检索链路 3 身份）**：单库检索 / 多库检索 / 无命中兜底 各一条断言
  验收标准: 存量对比无退化；3 条身份断言通过；检索日志含模型/表/命中数

- [x] T-07 多模型分组扇出 + RRF 融合 + 查询嵌入按模型缓存
  关联: R-03
  依赖: T-06
  验证方式: ①两个不同模型的库各放可命中文档 ⇒ 同题提问时**两组命中都进入最终上下文**（来源可标注）；②RRF 融合顺序符合名次融合预期（构造 A 组第 1、B 组第 1 的用例）；③查询嵌入调用次数 = 不同模型数（第二次命中缓存则不计）；④日志断言：扇出 INFO 含 命中库数/分组数/各组命中数/融合后条数/耗时
  验收标准: 跨模型召回完整 + 融合顺序正确 + 调用次数正确 + 日志字段齐备

- [ ] T-08 模型不可达降级：该库走关键词兜底并在结果中显式提示
  关联: R-03
  依赖: T-07
  验证方式: ①桩不可达模型 ⇒ 该库降级为关键词且响应带提示字段；②其它库的向量检索不受影响；③日志断言：WARN 含 库id/模型/降级方式/影响条数
  验收标准: 降级可见且不静默漏查；其它库零影响

  验收标准: 四场景 + 日志断言；清单字段齐全可支撑决策

- [ ] T-10 重建任务：后台执行（进度可查、失败清单可重试、断点续跑）+ 完成后原子切换绑定 + 期间检索降级并提示
  关联: R-04

## 5. 校验重构、升级与工具箱（R-05 / R-07 / R-08 / R-09）

- [ ] T-11 维度校验按库重构：`EmbeddingDimensionResolver` 由"全表一致"改为"该库绑定模型 ↔ 其向量表"判定
  关联: R-05
  依赖: T-04
  验证方式: ①两库绑定不同维度模型 ⇒ 各自写入均成功（不再互斥）；②某库表维度与绑定模型不一致 ⇒ 拒绝写入并给"重建/重新绑定"指引；③单模型部署下**不误报**；④**身份对照（resolver 3 身份）**：写入入口校验 / 模型切换后缓存失效 / 实时维度解析（不滞后）各一条断言；⑤日志断言：拒绝 ERROR 含 库id/模型/表维度/期望维度/处置
  验收标准: 五组断言通过；拒绝场景给可照做指引

- [ ] T-12 升级路径(a)：模型明确且可用 ⇒ **人工确认后**搬迁不重嵌（行数/维度对账 + 绑定与空间键写回）

  验收标准: 五组断言通过；人工闸有效；不重嵌有证据

- [ ] T-13 升级路径(b)：生成模型无法判定或已删除 ⇒ 默认走重建，且升级前提示影响面
  关联: R-07
  依赖: T-10, T-12
  验证方式: ①标记"无法判定"的库进入重建任务；②升级前输出规模预估（文档/分块/预计耗时）；③完成后绑定与空间键一致；④日志断言：升级批次 INFO 含 路径=b/受影响库数/预估

- [ ] T-14 运维工具箱：归属体检 / 表-模型迁移 / 验收报告（`--dry-run` 可用；复用已修正的 mktemp 写法）

  验证方式: ①`--dry-run` 前后数据零变化；②体检输出"模型↔表↔库"清单；③验收报告含五项（维度/约束/索引/重嵌完成率/抽样检索）；④**在无法升级平台的旧版本目标机**（仅拷脚本）跑通"体检→迁移→报告"
  验收标准: 四场景通过；报告可判定且含具体命令输出

- [ ] T-15 迁移/重建效果验收（R-09 五项）接入出货门禁与验收清单

- [ ] T-16 端到端回归与回滚演练：全新库路径 / 存量库升级路径 / 回滚到旧表窗口
